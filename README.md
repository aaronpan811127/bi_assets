# Self-serve BI Monorepo

Monorepo for multi-domain BI assets (Metric Views, Dashboards, Genie Agents) SDLC in Genie Code. Each domain forms a self-contained bundle which can be owned, developed, secured and deployed (with DAB) independently.

> 📖 **New here? Start with the [User Guide](user-guide.md)** — getting-started steps, workflow diagram, and the Genie Code cheat sheet.

## Domain-first structure

### Root folder contains

- `README.md` - What's in the repo
- `user-guide.md` - Getting started user guide and cheat sheet on developing using Genie Code
- `00_notebooks` - supporting utilities used by agents skills in Genie Code.
- `00_skills` - agents skills used in Genie Code calling `00_notebooks`
- `01_shared_metric_views` - DAB bundle with metric view definitions shared by more than one domain
- `.gitignore` - boilerplate gitignore file
- `.github/` - CI/CD pipeline (GitHub Actions)
- `00_tools` - installable `bi-tools` package: `dab_prehook` and `metric_view_deploy` commands used by the CI/CD pipeline

Remaining top-level folder represents a domain bundle:

- `finance_operations/`
- `supply_chain/`
- `another_domain/` (future)

### Each domain folder contains

**For development**

- `assets/dashboards/*.lvdash.json` - dashboard definition files.
- `assets/genie_agents/*.geniespace.json` (also shown as without json) - native genie agent definition files for edit. Not yet supported in git folder for deployment.

**For deployment (generated by system - Manual update not required)**

- `assets/genie_agents/*.genie_space.json` - genie agent definition files from corresponding `.geniespace.json` files for deployment.
- `assets/metric_views/*.metric_view.json` - metric view definition files containing all domain specific metric views used by dashboards or genie agents.
- `resources/dashboards.yml` - Databricks Dashboards definitions.
- `resources/genie_agents.yml` - Databricks Genie Agents definitions.
- `resources/metric_views.yml` - Databricks domain specific metric view definitions.
- `databricks.yml` - boilerplate bundle entrypoint for that bundle.

### 01_shared_metric_views folder

Shared metric views in this folder are manually maintained. When the system generate DAB bundle, it only creates domain specific metric views not declared as shared metric views.

- `assets/metric_views/*.metric_view.json` - metric view definition files containing all shared metric views used by dashboards or genie agents.
- `resources/metric_views.yml` - Databricks shared metric view definitions.
- `databricks.yml` - boilerplate bundle entrypoint for that bundle.

### 00_notebooks

Supporting utilities used by agents skills in Genie Code. Should be deployed to dev workspace. e.g. `/Workspace/shared_bi_utilities`

- `sync-genie-space` - create or update genie agents, i.e. `.geniespace.json` from `.genie_space.json` file.
- `generate-dab` - generate `.genie_space.json` from `.geniespace.json`, generate `resources/dashboards.yml`, `resources/genie_agents.yml`, `resources/metric_view.yml` and `databricks.yml` file.

### 00_skills

Deployed in `/Workspace/.assistance/skills/`

- `sync-genie-space` - create or update genie agents, calling `sync-genie-space`
- `generate-dab` - generate DAB files, calling `generate-dab`

## CI/CD Pipeline

CI/CD runs on **GitHub Actions** (`.github/workflows/`). Both workflows detect changed DAB
bundle folders (any top-level folder containing a `databricks.yml`) using
`.github/scripts/detect-changed-dabs.sh`, then run the Databricks CLI against each one.

The `dab_prehook` and `metric_view_deploy` steps below are provided by the `bi-tools`
package in `00_tools/` (installed via `pip install ./00_tools` by the `setup-databricks`
composite action).

### CI Behaviour

Defined in `.github/workflows/ci.yml`, triggered on pull requests to `master`.

1. Detects changed DAB folders by diffing the full feature branch against `origin/master`.
2. For each changed DAB bundle runs:
   - `dab_prehook` — rule-based config validation
   - `databricks bundle validate` — schema and config validation
   - `databricks bundle plan` — shows planned changes without applying
3. Posts a summary comment on the pull request listing the validated bundles and overall status.
4. Fails the check if any bundle's validation fails.

### CD Behaviour

Defined in `.github/workflows/cd.yml`, triggered on pushes (merges) to `master`.

1. Detects changed DAB folders from the most recent merge commit delta.
2. For shared metric views bundle (deployed first, since domains depend on it):
   - `dab_prehook` — rule-based config validation
   - `databricks bundle validate` — schema and config validation
   - `metric_view_deploy` — deploy shared metric views
3. For each changed domain bundle runs:
   - `dab_prehook` — rule-based config validation
   - `databricks bundle validate` — schema and config validation
   - `metric_view_deploy` — deploy domain specific metric views
   - `databricks bundle deploy --auto-approve` — deploy bundle to Presentation
